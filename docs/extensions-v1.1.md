# v1.1〜v1.2 拡張の定義

仕様書 §15 で「初版では実装しない」とされた項目のうち、貯水池・観測井戸・河川から地下水への逆向きの浸透・設備の追加を、v1.1 で実装しました。あわせて、できごと・評価のメーター・用語集を足しています。仕様書が「別途定義する必要がある」とした部分の定義を、ここにまとめます。数値はすべて仮の値で、`Scenario.fs` で調整できます。

## A1 貯水池

- 場所と建設: 取水点の上流に1つ。投資 (費用 2,000、長期の試練では ×1.2)。建設した季節の終わりに完成し、次の季節から使える。入門 (チュートリアル) では建てられない。
- 状態: 貯留量 S (WU)。`GameState.ReservoirWU`。容量 5,000 WU (標準)。
- 操作: 方針に「貯水池の操作」 (`Policy.ReservoirOpWU`) を追加。正なら河川水を貯め、負なら放流する。
- 1季節の処理 (`Hydrology.reservoirStep`):
  1. 蒸発: 季節開始時の貯留量 × 蒸発損失率 (春 2% / 夏 6% / 秋 3% / 冬 1%) を失う。
  2. 貯める量 = min(操作量, 取水点の上流を流れてくる河川水, 容量 − 蒸発後の貯留量)。放流量 = min(−操作量, 蒸発後の貯留量)。
  3. 取水点の利用可能量 = 上流の河川水 − 貯めた量 + 放流量。
- 水収支: 貯水池の蒸発は「蒸発散」に、貯留量の増減は「貯留の増減」に数える。残差は他と同じくほぼ0。
- 見込み (`Forecast`): 予報の降水の範囲で、貯水池の操作を反映した利用可能量と、季節末の貯水量の見込みを出す。

## A2 観測井戸

- 区域ごとの投資 (費用 500)。完成した次の季節から効く。
- 効果 (`Groundwater.applyObservation`): 毎季節、推定の相対誤差が 40% ずつ縮み (下限 ±5%)、貯留量の推定は実際の値に近づく (誤差の向きは試掘と同じ隠しの偏り)。持続的揚水量の推定も、同じ割合で真の値に近づく。下限に達したあとも、貯留量の推定は毎季節更新される。
- 調査との関係: 観測井戸のデータのほうが精度が高ければ、調査の結果では推定を更新しない (悪化しない)。
- 誤差の幅は、プレイ中に区域タブで、実際の値の範囲 (数値) として見られる。

## A6 河川から地下水への逆向きの浸透

- 配分管理地点までの区域 (農地・市街地) で、区域に流れ込む河川水の一部が地下水へ浸透する。森林は流れ込む河川水がなく、湿地は配分地点より下流なので扱わない。
- 浸透量 = 浸透率 K × 浸透の強さ × 区域に流れ込む河川水。K は農地 0.16、市街地 0.06 (舗装・護岸で小さい)。
- 浸透の強さ (0〜1) は地下水位で決まる: 公開されている初期貯留量の範囲の中央値 Gref に対し、G ≥ 1.5 Gref なら 0、G ≤ 0.5 Gref なら 1、その間は直線。地下水を汲みすぎるほど、川の水が地下水に吸われる。
- 地下水の更新式: G(t+1) = G(t) + R + 河川からの浸透 − P − B。浸透した分だけ、取水点の利用可能量が減る。
- 推定値の更新 (`advanceEstimate`) は、浸透を知らない (地下水位の変化から推定する要素として残した)。観測井戸や調査で補正される。

## A7 設備・政策の追加

| 設備 | 費用 | 効果 |
|---|---|---|
| 雨水利用施設 (市街地) | 800 | 生活・産業用水の需要が 12% 減る |
| 再生水の放流 (市街地) | 1,000 | 河川水で供給した生活・産業用水の 25% が下流へ戻る。環境流水の予約には数えず、下流の流量に上積みされる |
| 節水キャンペーン (流域全体) | 500 | 農業・生活産業の需要が、どちらも 8% 減る |

再生水のぶん、用水供給の「流域外への供給」は、戻った水を差し引いて数える (水収支の式の用水供給は、再生水の還元を引いた値)。

## B1 できごと

- 季節のはじめに予告され、その季節だけ効く。シナリオの日程で、起こるターンが固定されている (乱数なし。v2.0-b で、確率で引く方式をやめた)。
- 種類: 財政の緊縮 (春の交付金 −40%)、臨時の補助金 (+600)、猛暑 (夏の農業需要 +25%)、工場の新設 (生活・産業の需要 +30%)、停電・ポンプの点検 (井戸の能力が半分)、電力料金の高騰 (揚水費が 2 倍)。
- 予告: 起こる季節のはじめに加えて、1季節前から「来季の予告」として方針パネルに出る (備えられるように)。
- 起こるシナリオ: 長期の試練 (毎ターン 35%)、渇水 (20%)。ほかのシナリオでは起こらない。

## B3 評価のメーター

方針パネルの上部に、5指標の現在の評価と、ここまでの総合ランクの見込みを出す。地下水は、隠しの真の値ではなく、プレイヤーが知っている推定値 (開始時の推定との比) で計算する。財政は、ここまでの1ターンあたりの残高の増減が続くとして、最終残高を見込んで評価する。

## B8 用語集

右パネルに「用語集」タブを追加。主な見出しには ⓘ を付け、マウスを載せると短い説明が出る。

## 仕様書からの変更点 (注意)

- 仕様書 §9 の「投資は2種類」に、上記の投資を足した。
- 仕様書 §6 の地下水の更新式に、河川からの浸透の項を足した (§15 で対象外とされていた項目)。
- 起動オプション `--funds <整数>` (試験用: 初期の残高を指定する) を追加した。


## v1.2 での見直し (費用対効果)

「何も使わない」が最良の戦略にならないよう、簡易プレイヤーで設備の価値を測り、次を見直しました。測定の方法と結果は `docs/playtest/cost-effectiveness.md` にあります。

- **地下水の収支の整合:** 揚水ゼロでも地下水が減り続け (農地: 平年で −164 WU/季節、渇水で −248、乾燥地で −827)、持続的揚水量と矛盾していたので、「直接涵養」を追加した。浸透した降水の一部 (区域ごとに 4〜20%) は、土壌に留まらず直接、地下水に入る。これで、持続的揚水量の範囲で汲み続けても、地下水が大きく減らない。
- **浸透改善の作り直し:** 流出係数を下げる方式をやめ、「大雨 (降水が平常の 220 mm を超える季節) の地表流出の一部 (区域ごとに 20〜50%) を、地下に導いて涵養に回す」方式にした。川の水が乏しい季節には川の水を減らさない。
- **超過の借り:** 真の持続的揚水量を超える揚水の累積 (超えた分だけ増え、下回った分だけ減る) が、持続的揚水量の 75% に達すると、揚水コスト上昇フラグが有効になる (従来の「貯留量が閾値を下回る」に加えて)。調査や観測井戸で推定が真の値に近づくほど、安全な揚水量を見極められる。
- **フラグの重み:** フラグが有効な区域は、井戸の揚水能力も半分になる (回復しない)。
- **経済:** 収入の単価を半分、交付金を 7 割に、揚水費を 0.20/WU に、井戸の維持費を 70 に。財政の基準 (目標残高) はシナリオごとに設定し直した (入門 2,500 / 平年 4,500 / 渇水 4,000 / 市街地拡大 4,500 / 乾燥地 4,000 / 長期の試練 7,000)。費用が、評価に響くようになった。
- **井戸の能力:** 平年系は元の 0.6 倍に (乾燥地は 1.3 倍)。
- **貯水池:** 容量 8,000 WU、費用 1,800、蒸発損失率を 6 割に。
- **観測井戸:** 観測のある区域は、揚水費が 25% 下がる。
- **総合評価:** 「最低指標 +25% で頭打ち」をやめ、0.6 × 重み付き平均 + 0.4 × 最低指標 の混合にした。頭打ちだと、最低の指標以外の改善が総合点に反映されず、設備の効果が見えなくなっていた。
- **乾燥地:** 降水をさらに 7 割に、帯水層の貯留量と井戸の能力を大きくして、地下水が主役のシナリオにした。
- **設備の入れ替え:** 高効率ポンプと井戸の増強は、どの場面でも独自の出番がなく、費用に見合わなかったので廃止し、節水キャンペーンを追加した。

## v1.2 の画面 (計器)

入力はすべて機材を模した操作部 (ハンドル式バルブ・放流設定器・サムホイール式の順位セレクタ・レバー・押しボタン・ナイフスイッチ)、表示は計器 (指針式メーター・水位計・桁カウンタ・警告灯) にした。計器の側には、操作の効果の説明を置かない。効果や言葉の意味は、「マニュアル」ページ (用語集をふくむ) にまとめた。

### 固定盤面・重複なし (v1.2.1)

- 画面は 1180×800 の固定の盤面 (Viewbox で拡大縮小)。スクロールは出さない。長い内容は、ページ送り (マニュアル・遊び方・運転日報・最終報告書) にした。
- 「運転計画書」という紙の体裁はやめた。方針は、読む計器と直す計器を並べた**運転ページ**で決め、右下のナイフスイッチで「運転開始」する。結果だけが紙の**運転日報**。
- 情報は1か所だけに出す。時期・気象・残高=ヘッダー / 区域の状態=地図の観測計器 / 予報・取水・揚水・貯水池=運転ページ / 主要行動と資金=設備ページ / 評価・重み・累計の費用=評価・財政ページ / できごとの予告・ヒント=地図の下 / 区域ごとの水収支=日報。
- 観測計器は、実際の観測で使われるものに合わせた。降水予報=貯留型雨量計 (水位計の形)、土壌水分=探針式の水分計 (DRY・MOIST・WET の帯のダイヤル。市販の水分計の表記)、地下水貯留量=観測井戸の水位計 (推定の幅は青いかっこ、閾値は赤い線)、貯水池=水位計+ゲートのレバー。
- 表記の方針: 漢字1字の略称は使わない。完全な語で書くか、実際の機器で使われている英語表記 (DRY / MOIST / WET) を使う。優先順位は、略称の接点を持つロータリースイッチをやめ、項目名を完全な語で表示するサムホイール式の順位セレクタ (▲▼) にした。
- 地図は、4区域を左端の川に沿って縦一列に並べた (幅 300 px)。空いた幅を右の盤 (880 px) に回し、左の列 (本体と、その下のヒント・できごとの表示灯) と右の列 (運転ページは揚水ポンプ・貯水池、設備ページは資金、評価・財政ページはシナリオの注記) に分けた。ヒントと表示灯は、どのタブでも見える。マニュアルは全幅。

### 設備の整理 (v1.2.2)

- **浸透改善を廃止した。** 測定すると、費用なしで持っていても効果が 0 前後だった。理由は構造的で、(1) 地下水の指標は、どのシナリオの最良の戦略でも 1.00 (満点) で頭打ちになる (揚水を持続量に抑える限り、地下水は評価の基準を割らない)。(2) 浸透改善は地下水の貯留量を増やすだけで、揚水してよい量 (持続的揚水量、隠しの値) は増えない。点数に響く経路がないので、調整では解決できないと判断した。
- **観測井戸は残した。** 測定上の効果は、調整後も 0 前後 (+0.00x) のままで、価値があるのは、推定の幅が狭まる (情報の価値) 点だけである。簡易プレイヤーは、この情報を使い分けられないので、測れない。揚水費の節約率を 25% から 60% に上げ、費用込みの純価値が、測定した5シナリオ (平年・渇水・市街地拡大・乾燥地・長期の試練) で 0 以上 (+0.003〜+0.013) になるようにした。人間の試遊で、効果を確かめる必要がある。
- ヘッダーの「残高」を「資金」に改め、残高に春の交付金を加えた、その季節に自由に使える額を出す (日報の間は、その季節の期末残高)。設備ページの「今季の交付金」「使える資金」の桁カウンタは、重複するので廃止した。
- 設備ページの主要行動の押しボタンは、全区域で同じ9個を同じ順に並べる。その区域でできないものは、暗くして理由を書く。

### 「作成する」と「拡張する」 (v1.2.3)

貯水池・灌漑効率・再生水に、2段階の整備を入れた。最初は小さく安く作り (作成)、あとで1度だけ拡張できる。どちらも1ターン (1季節) で完成し、次の季節から効く。設備ページでは、作成済みのとき、同じ位置のボタンが「拡張」に替わる。

| 設備 | 作成 | 拡張 |
|---|---|---|
| 貯水池 (森林) | 費用 800 / 容量 3,000 WU | 費用 700 / 容量 6,000 WU (2倍) |
| 灌漑効率 (農地) | 水路の改修 1,100 / 需要 −12% | 高効率の灌漑方式 1,500 / 合計 −22% |
| 再生水 (市街地) | 600 / 還元率 15% | 処理能力の増強 700 / 還元率 30% |

- 作成と拡張の合計の費用は、以前の1段階だけの費用より少し高い (貯水池 1,800 → 1,500、灌漑 2,000 → 2,600、再生水 1,000 → 1,300) が、拡張後の効果は、以前より大きい (灌漑 −20% → −22%、再生水 25% → 30%) か同じ (貯水池の容量は 8,000 → 6,000 で、価値はほぼ同じ)。
- 拡張は、作成のあとにだけ、1度だけ実施できる。長期の試練では、費用が同じ倍率で高くなる。入門では貯水池を建てられない。
- 井戸・観測井戸・雨水利用・節水キャンペーンは、拡張を設けていない。以前の「井戸の増強」は、能力が不足する場面がなく、価値が測れなかったためで、同じ理由で、井戸の拡張は入れていない。
