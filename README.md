# Red River — 小流域水資源管理シミュレータ (v2.0-c)

仕様書「小流域水資源管理シミュレータ 仕様書(第二版・修正版)」の実装です。v0.1〜v0.3 を経て、v1.0(4区域・12ターン)まで実装し、その後 AI テスターによるプレイテストを3回行って、6つのシナリオ (入門・標準・特殊×3・高難度) と、遊びやすさの改善を加えました。その後、仕様書で初版の対象外とされた貯水池・観測井戸・河川から地下水への浸透・設備の追加と、できごと・評価メーター・用語集を実装しました (`docs/extensions-v1.1.md`)。人間によるプレイテストは未実施です(後述)。

## 実行・テスト

```sh
dotnet run --project src/WaterGame.App                                     # ゲーム起動 (シナリオは遊び方の画面で選ぶ)
dotnet run --project src/WaterGame.App -- --scenario 渇水 --seed 7 --skip-intro   # シナリオ・シードを指定して起動
dotnet test                                                                 # 不変条件・シナリオ・UI状態のテスト
tools/ui-smoke.sh <公開済みアプリのフォルダ>                                 # 実画面 (Xvfb) で全シナリオを数ターン進める煙テスト
WATERGAME_TRACE=1 dotnet run --project src/WaterGame.App                    # 受け取ったメッセージを標準エラーへ出す (不具合の再現用)
dotnet run --project src/WaterGame.App -- --funds 9000                     # 試験用: 初期の残高を指定する (新しい設備を試すときなど)
```

要件: .NET 8 SDK。F# / Avalonia.FuncUI 2.0 (Elmish) / Avalonia 12。煙テストには Xvfb・xdotool・ImageMagick が必要です。

## 遊び方 (ゲームの内容)

流域は 森林 → 農地 → 市街地・工業 → 湿地 の4区域で、河川は上流から下流へ流れます。毎ターン(1季節)、気象カードの予報と「今季の見込み」を見て方針を決め、結果カードで「なぜそうなったか」を確認します。

- 河川から農業・生活産業へ供給する目標、下流に残す環境流水の目標(最低基準以上)。
- 区域ごとの揚水上限(井戸がある区域)。
- 河川水を貯めて放流する貯水池の操作 (貯水池を建てたあと)。
- 主要行動を1つまで: 地下水の調査(概査 → 試掘)・井戸の建設・設備投資・政策 (灌漑効率の改善と拡張・観測井戸・貯水池の建設と拡張・雨水利用・再生水の放流と拡張・節水キャンペーン)。
- 各年の春だけ、配分優先順位(農業・生活産業・環境流水の3項目)を並べ替えられます (その年の4季節で続きます)。
- 季節のはじめに予告される「できごと」(交付金の削減、停電、需要の急増など。長期の試練と渇水だけ)。
- 画面は制御盤で、1180×800 の固定の盤面です (窓の大きさに合わせて拡大縮小し、スクロールは出ません)。左の地図には区域ごとの観測計器 (土壌水分計・地下水の水位計・持続的揚水量メーター) が並び、右の盤は「運転」(読む計器と、直す計器: バルブ・放流設定器・優先順位セレクタ・揚水ポンプ・貯水池ゲート)・「設備」(押しボタンと資金)・「評価・財政」・「マニュアル」の4ページです。右下のナイフスイッチ「運転開始」で季節が進み、結果は紙の「運転日報」(3ページ) で読みます。同じ情報は2か所に出さず、計器の側に説明は置きません。操作の効果や用語は「マニュアル」にまとめています。
- 計画経済版 (v2.0-a, v2.0-b): 冬の季節の年次報告 (正確に報告 / 前向きに報告 / 重大な問題を隠す)・整合性リスク・監査 (リスクが 60 に達すると、次の季節に入る。乱数なし)・終了時の監査も入っています (`docs/v2.0-b.md`)。 入門を除くシナリオに、中央からの指令 (綿花の増産・工業用水の供給) が、2〜3ターンおきに届きます。達成すると補助金と上司の信頼が増え、未達だと信頼が下がります (信頼は年度の交付金に響く)。流域の実態・計画達成度・政治的評価は、混ぜずに別々に評価します。詳しくは `docs/v2.0-a.md`。
- 資材・建設遅延 (v2.0-c): 入門を除くシナリオで、工事 (井戸・設備投資) は、資金に加えて資材 (機械設備・建設資材・専門技術者) がそろわないと着工せず、標準工期のあとに完成します。資材は日程どおりに配給され (乱数なし)、足りないときは、手数料を払って融通 (あとで返す) できます。指令には、設備の完成を求める建設期限も加わります。詳しくは `docs/v2.0-c.md`。
- 最終評価は農業・生活産業・環境・地下水・財政の5指標。最終画面に、学習目標5つの振り返りと、推定と実際の地下水貯留量の比較が出ます。

### シナリオ

| シナリオ | 区分 | ターン | 内容 |
|---|---|---|---|
| チュートリアル | 入門 | 4 (1年) | 気象は固定 (春平年・夏渇水・秋少雨・冬平年)。ヒントが優先順位 → 概査 → 井戸 → 揚水の順に案内する |
| 平年 | 標準 | 12 (3年) | 降水は平年並み。全指標のバランス |
| 渇水 | 特殊 | 12 | 前半に少雨が続く。農業と環境流水の対立 (この2指標の重みが2倍)。できごとが起こる (毎ターン 20%) |
| 市街地拡大 | 特殊 | 12 | 生活・産業の需要が年に 20% 増え、舗装で流出係数も上がる。優先順位を年ごとに見直す |
| 乾燥地 | 特殊 | 12 | 降水が少なく蒸発散が大きい。地下水の調査と使い方が決め手 (地下水の重みが2倍) |
| 長期の試練 | 高難度 | 20 (5年) | 平年 → 長い渇水 → 厳しい渇水 → 回復。費用が高く資金が少ない。需要の増加もある。できごとが起こる (毎ターン 35%) |

シナリオは `Scenario.fs` のデータで定義され、`Scenarios.all` に足すと遊び方の画面に並びます。

## 仕様書に記載がなく、仮に決めた点

数値パラメータ(面積、係数、需要、費用、収入、交付金、閾値、気象カードなど)は**すべて仮の値**です。`src/WaterGame.Core/Scenario.fs` だけで調整できます。

### 流域と配分
- **配分管理地点:** 市街地区域の下流端。下流湿地の流出は配分地点より下流で河川に加わり、環境流水の予約量は「目標 − 湿地からの流入」で計算します。
- **配分優先順位の初期値:** 農業 → 環境流水 → 生活・産業。優先順位セレクタ (ロータリースイッチ) で、6通りから選びます(春のみ)。初期値では生活・産業が最後に削られるので、画面で注意を促します。
- **生活・産業用水:** 農業と同じく、河川水から供給する目標を設定し、不足分は地下水で補います。地下水は優先順位の高い用水から先に供給します。環境流水には供給しません。
- **市街地区域:** 舗装が多く流出係数が高い(0.55)。

### 地下水
- **地下水の動き:** 湧出 B = 湧出率(0.05/季節)× 季節開始時の貯留量。涵養 R = 土壌からの深部排水 + 直接涵養 (浸透した降水の 4〜20%)。さらに、地下水位が低い区域では、河川から地下水への浸透が起こります。涵養と浸透は期末にだけ貯留量へ加わります。貯留量に上限は設けていません。
- **隠しパラメータ:** 初期貯留量と持続的揚水量。公開されるのは範囲だけで、真の値は、その範囲の中の、シナリオが決めた位置にあります (乱数は使いません)。
- **推定値:** 未調査は公開範囲の中央値。涵養と揚水は公開情報なので推定側も同じ式で進め、概査(±25%)・試掘(±8%)で真の値に近い値へ更新されます。
- **調査の順序:** 概査 → 試掘の順。井戸は概査済み以上の区域に1本。
- **ソフト上限:** 推定された持続的揚水量を超える揚水は可能で、超過を警告します。罰則は貯留量の減少と、真の持続的揚水量を超えた分の揚水費1.5倍です。
- **揚水コスト上昇フラグ:** 井戸のある区域で、貯留量が閾値を下回るか、真の持続的揚水量を超えた揚水の累積 (超過の借り) が持続的揚水量の 75% に達すると有効になり、以後は解除されません(揚水費の倍率 2.0、井戸の能力は半分)。井戸がない区域は、自然な減少だけでは立ちません。

### 財政・投資・評価
- **交付金:** 毎年の春ターンの開始時に受け取ります。残高は翌年度へ繰り越します。
- **収入:** 農業・生活産業それぞれの充足率 × 元の需要 × 単価 (v1.2 で半分にして、費用が評価に響くようにしました。入門は厚いまま)。灌漑効率改善で需要が減っても、同じ生産なら収入は変わりません。
- **任意行動と必須支出:** 調査・建設・投資は「残高(+春なら交付金)」の範囲でしか選べません。井戸の維持管理費と揚水費は必ずかかるため、残高がマイナスになることがあります(警告を出し、評価で減点します)。
- **完成の時期:** 井戸と設備投資は、実施した季節の終わりに完成し、次の季節から効きます。
- **評価:** 5指標の重み付き平均 (0.6) と、最も低い指標 (0.4) の混合で、S(≥90%)/A(≥80%)/B(≥65%)/C を判定します。重みはシナリオごとに違い、最初のターンに画面に出ます。
  - 地下水: 終了時/開始時の貯留量を、シナリオごとの基準比 (平年 0.70 など) で割って満点を1とし、揚水コスト上昇の区域ごとに 0.15 を引きます。
  - 財政: 最終残高がシナリオごとの基準以上で満点。基準未満は比例で、一度でもマイナスになると 0.2 引きます。
- **操作しやすさ:** バルブやダイヤルは 50 刻みで、右端付近は需要ぴったりに丸めます。前の季節の設定 (需要の何割か・環境流水の上乗せ・揚水上限) は次の季節に引き継ぎます。
- **プレイ時間:** 最終画面とログに、全体の所要時間と方針決定の平均秒数を出します(目標: 目安: 15〜25 分、45〜90 秒/ターン)。

## 既知の限界

- 取水点の利用可能量には地下水湧出が含まれるため、地表流出(係数と降水量から計算できる)を引くと湧出の合計が逆算できます。区域ごとには分離できませんが、完全には隠せていません。
- テスターはすべて AI で、人間の試遊は未実施です。難易度の数値 (特に長期の試練) と所要時間は、人間が遊ぶと違う可能性があります。
- 貯水池・高効率ポンプ・井戸の増強などの効果の大きさ (費用に見合うか) は、簡易プレイヤーの測定では小さめで、人間の試遊での確認が必要です (`docs/playtest/round4-summary.md`)。
- UI の確認は、仮想ディスプレイ上でクリック操作を自動化して行いました。実機でのフォントや操作感は未確認です。
